JetDose app map

A snapshot of how JetDose works, from commit bb0c068. It can drift as the code changes.

What the app is

A web page that plans when to take each medicine during a trip across time zones, plus a tiny Node server. The planning runs in the browser, so the plan works offline. The server only serves files and, when an API key is set, asks Claude to read a medicine sentence.

One action, end to end: "Plan my doses"

Reference route (3 stops)

  1. public/js/app.js → makePlan: reads home city and trip from saved state and calls the planner.
  2. public/js/planner.js → planMedicine: the kernel. Each dose is due one usual gap after the last; it moves toward the closest usual local time by at most flexHours. planMedicinePlain builds the plain-converter comparison.
  3. public/js/app.js → renderPlan and doseRow: groups doses by day and place and shows local time, home time, gap and reason.

This route was not toured interactively; it is a guide for reading the code.

To change this, start here

  • Default flexibility per timing type: DEFAULT_FLEX in planner.js.
  • Meal times for "with food" medicines: MEALS in planner.js.
  • How Claude reads a sentence: the SYSTEM prompt and the Medicine schema in server.js.
  • Rules used offline: parseMedicineText in parser.js.
  • Cities and time zones: CITIES in tz.js.

A practice to reuse

The PRD criterion "doses keep their spacing" became the test every JetDose gap stays within the medicine's flexibility in tests/planner.test.js. A second test, written after trying a Mumbai → New York trip, exposed doses drifting for days when they could simply swap morning and evening (recorded under Revisions in devpost/checklist.md). Writing the behaviour as a checkable rule first made the flaw visible as soon as a new route was tried; the same approach works for any logic-heavy feature.

For the ML/LLM goal: compare server.js (Claude with a Zod schema) with parser.js (hand-written rules) on the same sentences. The schema forces the model to return the same shape the rules return, so the rest of the app does not care which reader ran.

Run it again

npm install, then npm start and open http://localhost:3000. Run npm test for the planner and reader tests.
